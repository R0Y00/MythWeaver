# Agent 约束修复：工具协议、执行模式与回执核验

## 问题由来

v0.8 的猜数字创建验收走了执行模式，漏测了方案模式的失败路径。用户实际操作中，方案助手把不存在的插件命令传给游戏能力查询，服务端拒绝后直接结束请求，只显示 `FORBIDDEN_TOOL`。创建玩法快捷入口还会沿用旧会话模式，导致用户要求“实际创建并测试”，却进入仅生成方案的路径。

错误被拒绝是必要的，但只拒绝并把内部错误显示给用户，不构成可用的 Agent 控制流程。本轮修复从提示词补丁推进到真实调用协议。

## 查阅的专用场景代码

- [Concordia / SwitchAct](https://github.com/google-deepmind/concordia/blob/main/concordia/components/game_master/switch_act.py)：根据行动类型分派处理组件。
- [Concordia / EventResolution](https://github.com/google-deepmind/concordia/blob/main/concordia/components/game_master/event_resolution.py)：将参与者提出的行动与事件结算分开。
- [Quilltale / GameMaster](https://github.com/Aeesh/Quilltale/blob/main/src/agents/game_master.py) 与 [WorldState](https://github.com/Aeesh/Quilltale/blob/main/src/world/state.py)：叙述与结构化状态变更分开，状态层承担修改检查。

本平台采用的具体工程方法见下文；没有移植这些项目的固定角色、地图、战斗或 NPC 结构。

## 代码层面的约束

### 工具目录与执行入口使用同一份协议

`agent_contracts.py` 将共享命令目录编译为工具参数的 JSON Schema：

- 能力查询的命令名是枚举，不是任意字符串。
- 执行命令的 `kind` 与 `payload` 通过 oneOf 绑定，不只检查“payload 是一个对象”。
- 每轮调用前按本轮实际开放的工具快照校验名称和参数。
- 未暴露的插件工具、错误字段或不存在的命令在进入处理器前被拒绝。
- 新安装插件在下一轮重新注册后才可调用，不能在同一批中猜测尚未暴露的工具名。

模型依然可能输出无效参数。程序会拒绝它，并将结构化错误回传模型；服务端不会因为提示词说“可以”就放行。

### 方案预演禁止间接运行插件代码

过去事务预演可能通过交互或流程间接调用已有插件。数据库回滚无法撤销插件外部副作用，所以“没有提交数据库”不能代表“没有执行代码”。

现在方案预演进入独立执行上下文，插件运行入口首先检查该上下文。计划即使通过 submit 或流程尝试间接执行，也会在启动插件 worker 前被拒绝。数据库变更仍回滚，并向用户说明需要执行模式。

实际执行与明确的连续试玩继续允许运行管理员信任的插件。这不是 OS 沙箱，不削弱管理员在执行模式下安装和运行代码的既有能力。

### 已回复与回执核验通过分开

`finish_task` 要求提交 1–12 条显式检查：每条含真实工具回执的 `receipt.call_id`、JSON Pointer 路径及预期 JSON 值。

服务端检查：

1. 回执来自本任务。
2. 对应调用确实成功完成。
3. 不能引用进度描述、其他任务或伪造编号。
4. 指定路径确实存在，实际 JSON 值与预期匹配。

通过后才记录 `completed`，网页显示“已验收”并保留检查依据。普通文字结束仍记录 `answered`，执行任务页面显示“已回复 · 未验收”。核验工具必须单独调用，不能和仍将执行的其他操作混在一批。

回执编号由程序显式放入每次工具结果的 `receipt` 字段。真实模型测试发现，仅把协议 tool_call_id 放在消息元数据中，不足以让模型可靠引用它，因此没有要求用户自行查找内部 ID。

**边界：程序验证的是提交的显式检查和真实回执，不是自动证明自然语言目标已经被完整理解。** 模型可能遗漏验收条件，插件也仍是可信代码；不能据此宣称已经解决所有游戏设计正确性、任意插件安全或目标理解问题。

## 界面修复

- 新建会话默认执行模式。
- 点击“创建一个新玩法”明确切换执行模式。
- 未成功生成方案时提供“改用执行任务”入口，保留原始请求。
- 失败的读取显示失败，不再统一展示绿色“读取完成”。
- 方案失败明确说明没有执行游戏修改。

## 验证

`tests/test_agent_contracts.py` 覆盖未知工具、错误命令载荷、方案运行插件、预演回滚、跨任务或伪造回执、错误值及成功核验。现有计划、插件和会话测试继续回归。

v0.8 原有的 213 项测试不代表上述问题此前已经覆盖；约束修复后完整回归为 219 项。显式回传回执编号是随后由真实模型复测发现并补上的协议修复，另有 26 项针对性回归通过。

真实 deepseek-flash 复测：原截图的方案请求正确说明执行模式边界，没有生成无效修改；只读执行任务在 3 轮内通过 `finish_task` 核验真实定义版本，没有任何游戏变更。测试在先前的独立 schema 进行，不替用户在正式游戏重建或测试玩法。本机修复版本为 v0.8.1。
