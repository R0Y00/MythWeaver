# v0.9.6：取消说明字数上限与开放执行预算

## 已取消的固定限制

- 平台 `player_instructions` 原4000字符、`agent_instructions` 原6000字符。
- 游戏 `player_instructions` 和 `instructions` 原4000字符。
- 管理员统一助手当前请求原8000字符输入框及服务端校验。
- 模型路由输出预算原256–16384 tokens固定范围；现在填写正整数，实际支持范围由服务商决定。
- 模型请求超时原10–120秒范围；现在填写非负整数秒，0表示不限。
- 插件manifest `timeout` 原1–60秒范围；现在填写非负整数秒，0表示不限，可由Agent创建插件版本时指定。

说明在JSONB中完整保存，管理网页不再限制这些文本框长度。玩家模型收到完整的平台与游戏说明，不把说明计入“可见数据大小”的预算。不会为了通过旧限制而默默截断说明。

## 可以让管理 Agent 修改的预算

平台规则页面新增“Agent执行预算”，与 `platform_rules_read/update` 使用同一配置。管理Agent可以自然语言提出变更，按当前会话审批策略生效。

| 字段 | 默认值 | 生效范围 |
| --- | --- | --- |
| `agent_max_steps` | 24 | 新建及继续任务的模型请求轮数；0不限 |
| `agent_timeout_seconds` | 900 | 下次任务run/resume的总运行时限；0不限 |
| `player_timeout_seconds` | 90 | 玩家模型决策总时限；0不限 |
| `agent_tool_calls_per_turn` | 4 | 后续模型响应每轮工具调用数量；0不限 |
| `player_data_context_chars` | 40000 | 玩家可见记录、交互、事项等资料预算，不含说明；0不限 |
| `simulation_action_limit` | 20 | 每次结构化试玩的行动数量；0不限 |
| `simulation_chat_limit` | 8 | 每次真实聊天试玩的消息数量；0不限 |

例如对助手说：

> 把任务轮数设为不限，任务运行时限改为1800秒，聊天试玩允许20轮，其余不动。

应只提交对应平台字段，仍需审批或会话自动同意。说明文字不能自行跳过审批。新版本默认保留原有预算，不因更新自动扩大现有任务权限。

玩家模型决策总时限和模型服务商单次HTTP请求时限是两层配置；取消前者并不会取消后者。安装依赖的子进程也仍有独立时限。

## 长文本工具读取

一次性把所有长说明塞进工具回执，会使回执大小超过限制。本轮为 `platform_rules_read` 和 `list_controls(section=policy)` 增加 `instruction_offset`、`instruction_limit`，长说明返回明确的 `instruction_pages` 元数据：原文总长度、当前片段长度和下一页位置。

这是读取分页，不是保存截断。Agent修改已有长说明前须读完必要页，不能把第一页当完整原文覆盖。直接Web配置GET接口仍提供全文，模型所用的运行说明也不分页。长说明修改的执行回执同样返回分页元数据，避免“实际已保存但回执太长被报告失败”。

## 保留的其他限制与原因

本次没有宣称平台、数据库或模型资源无限。审计中仍保留：

- 管理登录、审批、玩家字段/受众权限、版本并发校验、工具参数schema与完成证据校验。这些是执行与权限规则，不是说明长度限制。
- 输入包体、工具/模型响应、插件输出与源码大小、进程资源，以及固定协议和数据库标识长度。配置与Agent接口包体提升至1MiB；服务商自身的上下文容量、最大输出和限流仍独立生效。
- 一次原子命令批次最多8项、同时执行任务数量、读取分页、流程结构、普通游戏/模板/模块描述字段、已保存输出字段和插件安装资源限制等。本轮没有把所有内核限制全部取消或开放给模型修改。
- 旧计划/只读讨论兼容接口仍有各自预算；新管理工作区走统一Harness，使用上表设置。
- 审批仍针对具体操作和状态，不能由Agent通过修改预算把自己切到自动同意。

这些界限会给出具体错误；不同类型的限制不再统称为“4000字上限”。

## 更新与验证

不需要数据库DDL迁移，旧规则没有新字段时使用默认值。通过更新包覆盖源文件与预构建网页，保留 `.env` 和 `.runtime`，重启后刷新页面。代码同时提交GitHub，其他电脑本轮可直接使用更新包，无需改为Git部署。
