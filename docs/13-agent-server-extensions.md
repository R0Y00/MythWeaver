# Agent 可定制的服务端行动

2026-10-29 增量。此前代码插件只能作为计算工具使用，效果通常写回一个字段。现增加通用 `extension` 协议：Agent 编写处理器，管理员通过定义授权其读取范围、可写字段和消息能力，平台执行事务与投递检查。匿名代号、交易、对抗、协作等都不作为核心必备玩法。

这也修正此前“匿名身份映射、多人结算、不同战报必须各开发一个固定功能”的说法。这些可以由 Agent 创建数据模型和代码实现；核心需要提供可组合的能力入口。

## 配置入口

`inspect_runtime` 返回 `extensions` 的完整协议。`rule`/`manual` 交互，及工作流的 `effects`/`manual` 步骤都支持：

```json
{
  "extension": {
    "plugin_key": "anonymous_transfer",
    "tool": "handle",
    "reads": [{"type_key": "account", "fields": ["owner", "alias", "credits"], "scope": "game"}],
    "writes": [{"type_key": "account", "fields": ["credits"], "scope": "game"}],
    "messages": true
  }
}
```

这是玩法配置示例，不是平台固定账户结构。授权类型与字段必须存在；scope 支持 `own` 或 `game`。可写类型必须同时授权读取，不允许通过玩家行动修改 `owner_field`。同一步骤不能同时使用 extension 和旧 effects，多个步骤可组合。

输入由服务端构造：

```json
{
  "actor": "qq:71001",
  "input": {"target_alias": "黑鹿", "amount": 3},
  "records": [{"id": "记录ID", "type_key": "account", "version": 1, "data": {"owner": "qq:71001", "alias": "白鸦", "credits": 10}}]
}
```

实际 records 包含 reads 授权范围内的记录和字段，最多 200 条、总输入 128000 字符。这些资料交给可信代码处理器，**不加入玩家模型上下文**。模型只提交交互输入，例如代号；插件可在服务端把代号解析成内部记录，检查余额、资格和玩法条件。

输出形状：

```json
{
  "updates": [{"id": "记录ID", "changes": {"credits": 7}}],
  "messages": [{"recipient": "qq:71001", "text": "已向代号黑鹿转移3点。"}]
}
```

最多 20 条记录修改、20 条消息。更新只能命中读取范围中的记录，且符合 writes 的类型、字段和 own/game 范围；重复目标、跨游戏目标、归属修改和非法 schema 均拒绝。更新仍经过流程锁、引用检查、版本更新和审计。更新、私聊排队、行动回执在同一事务中提交，任一项失败全部回滚；原请求幂等键重发不重复结算或排队。

消息需显式授予 `messages:true`。接收者只能是实际发起者或读取范围内记录的归属者，必须已绑定本游戏私聊，且通过参与资格检查；不能指定任意群或游戏外接收人。发送使用已有 Outbox/OneBot 私聊通道，真实投递在提交后完成，失败/未知状态使用现有投递管理处理。不同正文由管理员可信插件生成，平台不替管理员判断哪些线索应公开。

`manual` 交互批准后才调用处理器，保留原玩家 actor。工作流人工节点的输入为 `{input:发起输入, answers:{步骤标识:管理员填写内容}}`，处理器可使用 GM 指定的实际数值、分支或文案。裁决阶段的读取依赖变化时拒绝旧行动。拒绝事项不会运行处理器。

## Agent 的工作方式

管理员可直接描述：

> 创建匿名资源转移玩法。玩家只看自己的余额，按代号指定目标。双方余额同时更新，接收者不知道来源。特殊转移由我决定实际数量，决定后分别私聊通知。请创建所需类型、交互和代码插件，安装测试，再读取实际结果确认。暂不绑定真实QQ。

Agent 可以通过现有 `plugin_draft/install`、`module.put` 等工具完成配置，之后用同样的工具修改算法、字段、流程与受众正文。玩家不能创建/安装代码；底层插件工具还需 `player_enabled:true` 才能由玩家行动触发。scope=game 是授予指定可信处理器的服务端能力，不会变成玩家的共享写权限。
