# v0.12.0：复杂任务、上下文成本和管理工作区

这次针对“工具返回过大→重新读取→大段配置输出截断→无效参数重试”这类链路修改执行器。不能据此承诺任意复杂玩法不再中断。

## 按需工具参数

每次发给模型的 `execute_commands` 保留真实命令名称和统一参数外壳，不再重复嵌入所有命令的完整 payload schema。模型用 `inspect_capabilities(kinds:[...])` 读取当前需要的几个命令。服务端保留完整 schema，审批前仍逐字段校验；不是放宽执行权限。

同一份命令工具序列化定义，从 23,834 字符降至 1,156 字符，减少约 95.1%。这是该工具定义的字符比较，不是整次任务的 Token、账单或时延减少比例；具体仍以服务商回执为准。

## 完整回执和小范围修改

工具执行的完整结果保存在原 `ToolExecution.result`。模型只接收有明确 `partial=true` 标记的摘要和 `stored_result` 续读入口，页面和最终验收仍使用完整回执。大结果不再被改写为 `TOOL_RESULT_TOO_LARGE` 失败。

`read_tool_result` 按本任务的 `call_id` 和 JSON Pointer 读取指定字段，使用 offset/limit 分段，返回 `next_offset`、字符总数和完整性标记。它不重新执行原工具，不可读取另一个任务的回执。旧版本已经丢弃的完整结果无法凭空恢复。

已有模块可以先用 `preview_module_patch` 校验，再申请 `patch_module`。修改使用刚读取的定义版本和明确的模块内路径，支持 test/add/replace/remove。服务器从真实 manifest 构造局部修改，再通过原 `module.put` 事务、校验和检查点路径执行。原值或版本不符会拒绝；未指定字段保留。新模块仍用 `module.put`，没有限制 GM 创造新玩法。

局部修改遵循现有审批规则，也纳入玩家配置交接验收；跨空间使用时指定目标空间。只预览不执行写入。

## 稳定上下文和格式恢复

长任务压缩时保留原始目标、管理员后续决定、最近的阶段进度和回执索引，调用与工具结果成组保留。压缩后的前缀会复用到下一个压缩边界，减少每轮改变早期上下文而破坏缓存的问题。原始工具结果和执行参数仍在任务记录里；模型读取的是快照，不代表旧数据永远是当前状态。

协议兼容仅处理完整响应中的两类确定性差异：服务商直接返回参数对象、JSON 字符串内的字面控制字符。统一编码后仍走完整协议校验和审批。缺失括号、未闭合字符串、重复键、非有限数值不猜测修复；截断响应不执行。失败记录保留工具名、参数长度及解析位置，不倾倒原始业务参数或服务商错误正文。

保留连续无效响应停止机制，不通过无限重试掩盖错误，也不自动提高管理员配置的单次输出上限。阶段进度由 `record_progress` 保存，不能作为最终验收证据。

## 工作区

- **进展**：当前阶段、已完成和接下来、必要的中断恢复入口。
- **已生效修改**：区分源码保存、插件启用、配置和数据修改。
- **检查与验收**：区分定义校验、插件测试、真实玩家模型对话及最终验收。
- **用量与诊断**：按本任务真实响应累计输入、输出和缓存命中；没有上报的字段显示“未报告”。缓存命中包含在输入中，不重复相加，也不直接换算费用。

完整技术过程默认折叠，玩家助手面板改为按需打开。状态卡不再以查询次数和模型轮数为主要内容。HTTP 域名访问时复制会尝试浏览器兼容路径；仍失败会给出可选中、手动复制的诊断文本。

## 参考和验证

采用通用模式，不依赖某个模型厂商专用的工具发现 API：

- [Anthropic：按需发现工具与缩减上下文](https://www.anthropic.com/research/advanced-tool-use)
- [Pi：带有明确续读入口的分段读取](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/tools/read.ts)
- [Pi：保持消息边界的上下文压缩](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/compaction/compaction.ts)
- [DeepSeek：自动缓存与命中用量字段](https://api-docs.deepseek.com/guides/kv_cache/)

受控 DeepSeek Flash 联测使用虚构的大模块，单次任务最多 10 轮、单次输出上限 3000，实际 7 轮通过局部修改、保留其他字段和实际回执验收。累计输入 122,306 Token，其中缓存命中 105,600；输出 2,734。这不是与旧版的对照账单，不能外推所有玩法的费用下降比例。

数据库测试采用独立临时 PostgreSQL，真实模型联测也只使用虚构数据；不发送 QQ，不更新正式游戏，不启动正式平台。页面组件、用量与 HTTP 复制兼容有自动检查。本次本地浏览器无法连接预览，视觉和滚动体验尚未验收；临时预览已关闭。

完整自动回归 421 项通过；最后补充的回执分页目录、格式反馈、局部修改和玩家交接等针对性回归 58 项通过（含重复项）。页面状态、用量累计、HTTP 复制兼容 17 项检查和前端构建通过。没有用增加总轮数或输出上限来取得这些结果。
