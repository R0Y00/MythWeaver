# v0.5：管理员配置、玩家参与

平台以 Agent 为主要操作入口。管理 Agent 把管理员的自然语言要求转成持久定义、规则、流程和参与策略；玩家 Agent 理解玩家请求，读取授权资料，并通过同一事务服务执行已开放的交互。管理台用于检查、试运行、接管和恢复。

两种身份共用业务执行服务，但工具权限不同。玩家模型没有管理命令、SQL、任意代码或直接写记录工具；管理员 Agent 仍可完整操作已经支持的游戏业务。

## 本轮实现

- `policy.update` 新增 `player_agent_enabled`、`player_instructions`。默认关闭；管理端的 `instructions` 不进入玩家模型。
- 类型新增 `player_access: {owner_field, read_fields, shared_write?}`。归属字段为 `qq:数字` 字符串；只有自己的记录或 `public` 记录可读，并且只提供列出的顶层字段。未配置的类型对玩家模型不可见。
- `public` 仅开放读取。操作其他人的记录还需要管理员显式设置 `shared_write: true`；玩家不能修改归属字段。启用玩家 Agent 后，直接规则指令同样执行目标写入检查。
- 交互新增 `player_enabled` 和 `player_description`，默认不向玩家 Agent 开放。模型只能调用 `submit_action` 提交一个已开放交互，服务端校验参数、引用、身份、条件和目标授权。
- 玩家会话按游戏和 QQ 身份隔离。保留最近六次请求作为对话线索，不重放旧回复里的资料，避免授权变化后继续泄露旧字段。
- 同一玩家同时只处理一个请求。模型单次请求、整体 90 秒上限、响应 256 KB 上限、玩家上下文 40,000 字符上限。使用独立 `player` 模型任务，可在“模型管理 → 任务分配”配置。
- 玩家调用提交、扣减、追加、事件和执行回执在同一事务提交。相同请求编号不重复执行；旧回执在状态或权限变化后不再返回。
- 执行前重新比较游戏版本、权限、记录、流程与绑定状态。GM 改动后，旧规划失败并要求重新发起。检查点恢复会取消执行中的玩家任务及私聊入站任务。
- 复杂行动可进入已有 `manual` 交互或带人工节点的流程。裁决结果在该玩家下一轮查询时可见；未实现裁决后主动私聊通知。
- 私聊绑定使用 `channel.bind {group_id: "private-123456789"}`；原数字群号绑定保持兼容。一个 QQ 私聊最多绑定一个游戏。私聊仅受理 `/mw `（或自定义前缀）开头的文字，普通聊天不保存。
- 私聊入站、模型任务、出站分别处理，模型等待不阻塞群指令和出站泵。回复使用 OneBot `send_private_msg`；私有状态不转发到群。
- 管理员修改游戏时，取消该游戏尚未发送的私聊回复，避免旧权限资料继续排队投递。已经发往 QQ 的消息无法撤回。

## 使用方式

先配置“玩家 Agent”模型，再在管理 Agent 中描述需求，例如：

> 建立资料账户，记录归属、额度、资料列表和管理员备注。玩家只能看到自己的名称、额度和资料，备注保密。领取公开资料需要消耗三点额度；额度不足拒绝。特殊请求由我决定。启用玩家助手，暂不绑定 QQ。

管理 Agent 可以生成定义、规则和策略并预演，按管理员本次授权执行。模型实际理解与生成质量仍需真实模型验收，不能以提示词或模拟协议测试替代。

本地可选示例 `examples/private-player-agent.json` 演示同一链路，创建入口在示例列表。示例中的 `qq:1`、`qq:2` 是占位身份，未绑定 QQ。在“游戏设置 → 玩家试运行”选择 `qq:1`，先检查可见资料，再自然语言请求领取；试运行使用真实游戏事务，会修改此示例数据，不发送 QQ 消息。

两种管理员认证接口用于本机验收，不是对玩家公开的 HTTP 登录入口：

- `GET /api/games/{id}/player/records/qq:1`：检查此身份可见资料。
- `POST /api/games/{id}/player/turn`：`{actor:"qq:1", prompt:"领取资料", key:"唯一请求编号"}`。

真实私聊需管理员将示例身份替换为实际玩家身份，并明确绑定 `private-实际QQ号`。本轮没有替用户绑定真实会话或发送真实消息。

## 当前边界

这是一条可配置玩家参与闭环，不代表原聊天里所有玩法已经实现。仍没有通用背包文本导入、动态商店/库存模块、随机骰子、钓鱼表与装备修正、状态持续时间、每日刷新、PvP 结算、任意脚本扩展、费用金额预算或模块安装系统。

当前可配置固定规则的数字扣减、字段修改、列表追加、前置条件、人工裁决和既有无环流程。示例的固定资料领取不是完整商店或背包系统。玩家主动道具选择可通过多轮询问收集信息，但没有持久的“等待玩家回答”流程节点。

人工决定后需玩家再次查询；群内仍使用显式结构化指令，不把群聊交给玩家 Agent。权限粒度目前是记录归属与顶层字段列表，不支持任意受众角色或嵌套字段策略。

验证：121 项 PostgreSQL 隔离测试通过；前端 TypeScript 检查与 Vite 构建通过。模型测试使用模拟服务商，私聊投递使用模拟 OneBot；真实模型、真实 QQ 私聊与多人长局尚未验收。当前环境关闭了浏览器自动化，未声称完成新版页面的浏览器视觉验收。
