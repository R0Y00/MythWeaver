# v0.11.0：管理助手主动补齐、聊天承接与可见交接

GM 提供玩法目标，管理助手负责把目标落实为可用的玩家助手。GM 不必预先设计所有聊天分支、参数结构、权限位和测试。这个版本同时改动管理执行器、玩家执行器和管理页面，避免只把责任写进提示词。

## 管理助手负责什么

管理助手先检查实际玩家配置和原始需求，主动补齐职责与风格、行动说明、对象和参数含义、别名、缺参追问、同聊天补充/纠正/继续、必要确认、失败反馈和 GM 升级入口。没有要求交易、战斗或确认的玩法，不应凭空加入这些机制。

只有无法从现有资料推断、又会改变玩法的业务决定才询问 GM，例如价格、特殊效果、胜负条件或互相冲突的业务说明。不能把填写技术结构、选择权限位或准备测试当成 GM 的工作，也不能为了省事自行增加数量上限、消耗或剧情。

新增 `inspect_player_agent`，读取实际生效的全局/本游戏说明、群私聊入口、行动与完整输入结构、玩家契约、处理插件可用性、待确认数量和近期原话/解析/回执。可以按玩家与受众检查真正可见的资料。原文说明分页读取，不用摘要覆盖保存值。部分没有 QQ 绑定的配置可以先在隔离空间验证；“没有绑定”会作为待接入事项显示。

## 不再只凭保存回执验收

执行器检查本任务是否修改了已启用的玩家配置。涉及玩家说明、开放模块、相关插件等修改时，`finish_task` 需要引用：

1. 同一游戏、当前配置版本的交接检查，且没有阻塞项。
2. 当前版本至少三轮、有实际预期检查的真实玩家模型对话。
3. 有开放行动就实际调用；重要参数检查 `expect_inputs`，写资源检查记录字段。
4. 配置允许跨轮补充时，用 `expect_history_used=true` 核对实际使用了本聊天历史，不能靠重复完整句子代替。
5. 本任务保存了业务原文时，其覆盖表也须完成当前验收，不能忽略自己留下的未验证条款。

因此，三次问候、几个插件测试、保存成功或旧版本的对话都不足以宣布玩家配置完成。没有完成必要交接就结束答复时，执行器会要求助手继续验证。确实缺业务决定时，助手通过 `ask_admin` 保存进度并提出具体问题；回答后接着原任务继续。

这些检查能核对实际配置和执行证据，不能自动证明所有自然语言和业务语义都正确。测试的选择和覆盖仍然重要；GM 在管理页面可以看到原文覆盖及未完成项。

## 聊天能力的变化

平台自动为每个开放行动生成独立的完整参数工具，仍保留原来的通用提交接口。聊天助手不必仅依靠一个宽泛工具在不同玩法的参数之间猜测。

管理助手可以通过 `player_contract` 配置自然表达示例和关键字段语义。选择字段支持名称/别名映射稳定值，也能从玩家授权目录读取；数值字段支持常用中文数字和配置的单位换算。模型为关键字段提供真实原话依据，服务端在执行前核对。模型填错数量、选错枚举值、引用别人的私有目录或伪造其他聊天的依据时，不执行资源修改。

默认 `context_mode=conversation`：可以先选择对象，再补充次数；也可以在成功行动后说“再来三次”。历史目标和当前数量分别引用真实来源，当前明确纠正优先。只有 GM 明确要求单条消息完整时才使用 `message` 模式。避免串项不等于禁止跨轮补充；数组中的每项单独核对来源。

聊天助手可以在同一轮做多个只读查询。管理员开放 `player_batch=true` 的独立自动行动可以组合提交，全部成功或全部回滚；重复请求不重复执行。需要共享确认的多项操作继续使用一个含列表输入的交互，不能把一次确认拆成多笔偷偷执行。

这些是通用配置能力，不是内置商城或数量解析器。原话依据只能核对已配置的选择和数值，不是通用语义证明；否定、复杂指代和未列出的别名仍可能需要模型理解或追问。现有复杂插件本身是否正确结算，仍需独立的资源断言和业务测试。升级不会擅自重写每个旧游戏。

## 管理页面

助手工作区新增“玩家助手配置”面板，展示：

- 真实职责说明、模型与接收方式。
- 实际开放行动、必需信息、确认方式和跨轮示例。
- 需要管理助手补齐的缺口、处理插件阻塞与待确认数量。
- 近期玩家原话、答复、实际解析参数、读取过程和执行状态。
- 让管理助手补齐/排查的入口，以及按编号查看完整对话。

这些入口准备具体的管理请求，执行仍遵循会话审批设置。最新一轮执行过程默认展开，实际修改和测试结果在对话中直接显示，技术参数与原始回执继续折叠。宽屏使用侧栏，窄屏使用可关闭的面板，不要求 GM 阅读 JSON 才能理解是否完成。

## 默认不限轮数

任务默认 `agent_max_steps=0`、`agent_timeout_seconds=0`，表示不限总模型轮数和总任务时长。管理员仍可主动设置预算；服务商单次请求、插件执行超时和上下文容量独立。

迁移 13 将旧版默认值 24 轮、900 秒改为不限，其他自定义预算保留。如果以前特意设置的正好也是 24/900，这次也会转换，需要时可在平台规则页重新设置。全局为不限时，旧任务保存的轮数上限不再使运行中的任务停止；已经暂停或停止的任务不会在启动时擅自恢复。

取消、审批、真正缺少业务信息、外部错误仍会停止或等待。连续返回无效工具协议或持续跳过交接属于无有效进展，默认容忍 3 次后明确报错并保存进度；`agent_stall_limit` 可修改，0 表示不限。这与“做了 24 轮正常工作就停下”不同，不需要靠不断说“继续”推进正常任务。

## 更新与验证边界

通过 `update-platform.bat` 更新，不制作更新包。启动时自动运行新增迁移，保留现有游戏和配置。

本次加入了数量/选择核对、同聊天承接与纠正、动态目录隐私、多行动回滚与重试、参数断言、交接验收、业务覆盖、超过 24 轮持续执行、提问后原任务恢复及旧预算迁移等回归。

真实模型联测同时调用 DeepSeek Flash 管理助手和玩家助手：测试目标只有业务描述，不给管理助手现成模块或参数结构。管理助手自行经过 **48 轮**完成实际配置、连续对话、原文覆盖及当前版本验收，未要求人工续跑；随后对其生成的玩法另做 **6 轮**不同表达的补充检查，全部通过：别名、沿用目标并改变次数、已执行行动的歧义澄清、明确新增、最终累计值为 9。正式数据保持原样，测试没有 QQ 投递。

联测也确实暴露了管理助手把缺参追问误配为禁止跨轮补充，以及数量依据同时包含“一笔”和“四次”的问题。因此补了默认对话承接、跨轮示例检查、实际历史使用断言，以及含被拒绝参数的修复反馈。已执行行动后的模糊纠正保留追问；明确新增后继续执行，不悄悄改写历史。这组结果不代表所有玩法或任意自然表达均已可靠解决。

完整自动回归 **393 项通过**；后续协议/交接/审批回归 **43 项**、覆盖报告/交接回归 **49 项**通过（包含重复项）。最后的数量依据反馈与玩家执行回归 **44 项通过**。前端类型检查、构建及 HTTP 兼容检查通过，修改文件凭据扫描无发现。

日常平台及数据库保持停止；所有数据库和模型测试使用独立临时实例及虚构数据，不发送 QQ。前端进行类型检查、构建和接口检查。当前 Work 设置关闭了本地浏览器控制，未完成浏览器视觉验收；为此启动的临时界面预览已经停止。
