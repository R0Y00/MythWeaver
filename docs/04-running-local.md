# 本机运行与当前实现范围

> 新机器部署请以 [Windows 部署与迁移](14-windows-deployment.md) 为准：现已提供首次安装脚本、可迁移发布包、独立端口和可配置 NapCat；下文保留早期本机实现记录。

日期：2026-10-29 · 应用版本：0.4.0 · 状态：已扩展管理控制台，不代表需求全部完成。

## 1. 当前运行方式

按用户要求采用 Windows 原生进程，不使用 Docker，不安装系统数据库服务。

| 服务 | 位置/地址 |
| --- | --- |
| 平台 | http://127.0.0.1:8080，FastAPI 单进程，托管 React 构建产物 |
| 数据库 | 项目内 PostgreSQL 17，127.0.0.1:55432，仅回环监听 |
| 数据目录 | `.runtime/pgdata` |
| PostgreSQL 程序 | `.runtime/postgresql/pgsql/bin`，使用 EDB Windows 二进制发行包 |
| 后端环境 | `.venv`，Python 3.12 |
| QQ 协议端 | 用户提供的 NapCat 自动登录脚本，由 `start-napcat.bat` 包装调用 |
| OneBot 入口 | `ws://127.0.0.1:8080/channels/onebot/v11/ws` |
| 密码与协议密钥 | `.env`；管理员密码另存 `.runtime/credentials.txt` |
| 日志 | `.runtime/api.log`、`.runtime/postgres.log`、`.runtime/napcat.*.log` |

双击 `start-platform.bat` 启动数据库和平台，双击 `start-napcat.bat` 启动 NapCat。两个脚本以自己的目录为工作目录，不依赖打开终端的位置。`stop-platform.bat` 停止平台及项目数据库，NapCat 单独管理。

管理员密码只用于本机平台；OneBot Token 是独立随机密钥。不要公开 `.env`、credentials、NapCat 配置、数据库数据或备份。代码忽略这些本机文件和整个 NapCat 发行目录。当前只设计本机使用，未完成公网部署加固。

## 2. 首次重建环境

依赖版本固定在 `requirements.lock` 和 `apps/web/package-lock.json`。

```powershell
python -m venv .venv
python -m pip --python .venv/Scripts/python.exe install -r requirements.lock
cd apps/web
npm.cmd ci
npm.cmd run build
cd ../..
```

从 [PostgreSQL Windows 官方下载页](https://www.postgresql.org/download/windows/)指向的 [EDB 二进制包页面](https://www.enterprisedb.com/download-postgresql-binaries)取得 Windows x64 ZIP，解压后确保存在 `.runtime/postgresql/pgsql/bin/initdb.exe`，再执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

`setup.ps1` 在没有配置时生成随机密码，初始化项目数据库并创建数据库；不会覆盖已有 `.env` 或已初始化数据。NapCat 配置只增改名为 `mythweaver-local` 的反向连接；修改前备份到 `.runtime/napcat-onebot.before-mythweaver.json`，保留其他网络配置。

NapCat 的安装路径和账户目前固定在 `scripts/local.py`，沿用本次用户提供的安装位置。更换账号/版本时须调整路径与 `.env` 中 `ONEBOT_BOT_ID`，不能同时开多个相同账号连接争用会话。

## 3. 从空白游戏开始

1. 登录管理台，创建空白游戏。名称和说明可以修改。
2. 如果只想文字互动，不需要定义任何类型、人物、属性或阶段。
3. 需要数据时，在“定义与交互”新增类型和字段；“游戏数据”会自动出现相应表单。
4. 需要结构化提交时，新增交互，定义输入字段与处理方式。
5. “互动工作台”可以在本机提交测试文字，也可以处理 QQ 传来的待决定事项。
6. “历史与检查点”查看前后差异；导出当前快照。截图演示数据位于“本机试运行”，未绑定群。

类型与交互使用独立英文标识，显示名称可使用中文。图形字段编辑器目前支持文本、数值、整数、布尔、文本列表及必填设置；枚举、列表和嵌套结构可通过高级 JSON Schema 编辑，记录表单对应展示枚举控件或 JSON 输入。文本字段可以配置对象引用，提供选择器和服务端跨游戏/类型/归档检查；有效引用会阻止直接归档目标。详见 [流程说明](06-workflows.md)。

类型/交互可以停用。停用类型保留数据但不允许继续编辑；有现存数据的类型不能直接删除。定义变更会检查既有数据，拒绝不兼容修改；显式定义/数据迁移已实现，并自动保存安全检查点；不会自动猜测转换规则。

当前模式：

- `manual`：记录待决定事项，由管理员填写结果；若配置了数据规则，批准时才执行，拒绝时不执行。
- `record`：提交即记录；没有配置数据规则时不修改其他状态。
- `fixed`：记录并返回管理员预先填写的公开结果；绑定 QQ 时会在触发群回复该结果。

- `rule`：提交后执行已配置的数据规则。
- `flow`：启动关联的可选流程，按条件、自动步骤和人工节点推进。

规则编辑器提供字段赋值、数值增加、列表追加，支持常量或输入字段取值；通过输入字段传入目标记录完整 ID。每条交互最多 10 项变更，按 JSON Schema 校验并在同一事务执行，失败全部回滚。没有任意代码、表达式或嵌套字段路径执行。`record`/`fixed` 也允许显式配置规则。

自由文字 `_free` 可在设置中选择人工处理或直接记录。定义/游戏版本变化使已有待决定事项过时。带数据规则的人工事项记录目标版本，批准前目标已变化会拒绝执行，必须重新提交；填写的自然语言结果不自动推演成其他操作。

## 4. QQ 接入与指令

在“连接与诊断”中确认 NapCat 在线，再由管理员填写群号绑定游戏。未绑定任何群时，平台不受理群内游戏输入；不会主动去给联系人或群发测试消息。

仅处理明确命令前缀，默认 `/mw `，可在游戏设置修改；普通群聊不入库也不调用模型：

```text
/mw 帮助
/mw 提交 我想提交的内容
/mw 使用 自定义交互标识 {"字段标识":"内容"}
```

群参与者可提交已启用交互。当前没有 QQ 管理指令、个人 Web 入口或 QQ 到管理员权限的绑定；所有管理操作只能登录本机工作台完成。管理员可暂停参与、配置 QQ 用户白名单、封禁单个参与者，并限制每条交互允许的 QQ 用户；管理员网页操作不受玩家白名单限制。参与者管理不授予平台管理权限。

QQ 只返回受理编号、状态和明确配置为公开的固定结果。管理员在工作台填写的决定默认不自动发布到群，避免将私密裁决误发；公开发布工具尚未实现。

连接鉴权、账号匹配、echo 响应关联、心跳/断线、会话替换、inbox 去重和 outbox 投递由平台自有模块实现。发送后超时/断线的不确定消息标记 `unknown`，不会盲目重发；可在诊断界面手动重试 `failed/unknown`；`unknown` 必须确认可能重复送达。取消绑定或改绑后不投递旧游戏的排队消息。重连不保证补齐离线期间未收到的 QQ 消息。

本次已验证真实 NapCat 自动登录及反向 WS 握手、会话保持；没有绑定真实群，没有进行真实群收发测试。消息受理/回包/去重通过模拟 OneBot 与 PostgreSQL 集成测试验证。

## 5. 管理 Agent

在“模型管理”添加服务商、API 根地址、密钥与模型列表，再在“任务分配”中给计划助手和讨论助手分别选择模型。网页修改实时生效，不必重启。可配置输出上限、超时，以及 `max_tokens` / `max_completion_tokens` 参数名。连接测试调用 `/models`，验证凭据并展示实际列表，不代表所有生成/工具能力均兼容。

密钥以 Fernet 加密保存在数据库，网页只返回是否已配置。加密密钥由 `.env` 中的 `SESSION_SECRET` 派生：备份数据库时必须同时妥善保存 `.env`，丢失或改动此密钥会使已存 API 密钥无法解密。旧版 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 环境配置保留为未分配任务的后备配置。

服务需要支持 Chat Completions 的 function tools 格式；不绑定具体提供方或模型，不假设所有“兼容”服务完全支持相同参数。远程地址要求 HTTPS，本机模型允许 localhost HTTP。密钥不发给前端、不记入事件。格式依据 [官方函数调用文档](https://developers.openai.com/api/docs/guides/function-calling)，实际提供方仍需联调。

只有登录管理员打开“管理助手”并提交请求时才调用模型；普通 QQ 消息不进入管理 Agent。发送前界面说明：当前定义、对象数据和待决定事项会提交给所配置提供方。初始定义与资料预览上限约 60,000 字符；多轮消息上限约 120,000 字符，默认输出上限 4,096 tokens，可按任务调整，计划一次最多 8 个操作、一个同时进行的模型请求；默认超时 60 秒，可按任务调整；超出范围返回明确错误，不静默截断计划。

Agent 目前能规划定义变更、自定义对象创建/更新、内容提交、人工决定和流程启动/继续/取消。模型只返回计划；平台重新校验参数、在回滚事务中预演，再把具体操作展示给管理员。点击执行后以同一业务服务整批提交，执行失败全回滚；重复执行返回原结果。预览生成的新对象编号只是临时编号；同计划尚不支持引用前一步新建对象。计划 15 分钟有效，期间相关游戏状态变化会拒绝执行。

“助手工作区”保存计划、执行结果、耗时和失败状态；支持取消未执行计划，以及只读讨论。讨论助手读取当前定义/数据和最近 6 轮已完成讨论，不执行写操作。

v0.3 计划助手支持最多 4 轮模型请求、6 次只读工具查询，查询记录/历史/流程后生成计划；单次规划总超时 180 秒。界面可显式授权本次请求预检后直接执行，默认仍为先预演；可停止正在规划的任务。只读讨论的运行中取消尚未接入。没有后台自治长任务、费用金额预算或网页/代码/任意 SQL 工具。尚未配置真实模型密钥，已用模拟提供方验证协议和执行边界，没有真实模型质量或计费验证。

## 6. 备份与恢复验证

```powershell
.venv/Scripts/python.exe scripts/local.py backup
.venv/Scripts/python.exe scripts/local.py restore-check
```

前者将 PostgreSQL 完整备份保存为 `.runtime/backups/*.dump`。后者把最新备份恢复到一个新建的 `mythweaver_restore_*` 数据库，验证能读取游戏、事件和对象引用；不会覆盖正在使用的数据库。恢复验证数据库保留，方便检查。

Web 的 JSON 导出是当前状态及最近 200 条历史/提交的阅读快照，不能替代完整数据库备份，不能作为完整数据库恢复文件。

“历史与检查点”支持手动保存游戏检查点和在线恢复。检查点包含游戏名称、说明、定义、全部对象和全部提交。恢复前自动保存当前状态为安全检查点；恢复事务替换游戏业务状态并增加版本，审计历史不删除，待发送任务取消。带数据依赖的待决定事项和流程等待恢复后标记过时；检查点之后的流程标记已被恢复替代，流程历史继续保留。模型配置、参与策略、参与者与群绑定不回退；已发送 QQ 消息不能撤回。完整灾难恢复仍使用数据库备份和 PostgreSQL 工具。检查点不是任意事件撤销，也没有历史分支界面。

| 能力 | 当前状态 |

| 空白游戏、名称/说明编辑 | 已实现 |

| 自定义输入与 record/manual/fixed/rule/flow | 已实现；规则可赋值、数值增加、列表追加，支持人工批准 |

| 管理 Agent | 网页模型配置、多轮只读查询、计划/讨论历史、预演/本次直接执行、停止规划；真实模型待联调 |

| 参与控制与诊断 | 暂停/白名单/封禁/交互权限、收发队列、手动失败重试 |
| 模板复用 | 定义保存/导入/导出/创建新游戏，不复制数据和绑定 |

需求/技术设计文档描述目标能力，不能把未实现项理解为本版本已交付。数据库目前使用 SQLAlchemy 初始建表，并在 `Store.initialize` 中按 `schema_migrations` 执行显式追加迁移；尚未接入 Alembic。后续表结构变更必须增加版本迁移及备份，不能依赖 create_all 修改旧表。

## 8. 验证

```powershell
.venv/Scripts/python.exe -m pytest -q --tb=short
cd apps/web
npm.cmd run build
```

测试在 PostgreSQL 内为每个用例创建独立随机 schema，结束时只清理该测试 schema，不删除真实游戏。模型请求使用 HTTP mock，不花费 API 额度，不向真实 QQ 发消息。覆盖空白游戏、自定义数据、四种处理方式、停用、旧版本失效、并发/幂等、权限/跨游戏、事务回滚、JSON Schema 引用限制、登录/CSRF、OneBot 鉴权与回包关联、入站去重、Agent 预演/原子执行/失效和工具授权。

本机工具沙箱可能限制回环 TCP 或 PostgreSQL 子进程；正常 Windows 终端运行不需要 Docker。测试使用 `--tb=short`，避免第三方数据库异常的详细 traceback 展示本机连接凭据。

v0.4 共享能力见 [管理 Agent 游戏控制](08-agent-game-control.md)；v0.2 验证结果见 [控制台升级说明](05-console-upgrade.md)；当前能力见 [流程说明](06-workflows.md) 与 [首版验收跟踪](07-acceptance-status.md)。模型请求使用模拟提供方，真实模型质量、计费、真实 QQ 群收发仍待用户配置后联调。
