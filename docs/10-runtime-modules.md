# Agent 创建模块与功能（v0.6）

平台交付的是创建和运行能力的机制。管理员描述需求后，由 Agent 定义、创建、修改和组合模块；具体玩法不是平台必须内置的清单，也不要求管理员从固定功能菜单里选择。

## 已实现的扩展层

一个运行时模块包含任意组合的：

- `types`：新数据概念、字段、约束和玩家访问配置。
- `interactions`：新操作、参数、执行者、条件、效果、是否开放给玩家 Agent。
- `workflows`：可组合的自动步骤、分支与 GM 指定节点。
- `functions`：管理员或 Agent 编写的计算表达式，可以定义此前不存在的计算行为。
- `requires`、`enabled`、`revision`：依赖、启停与版本。

模块保存在游戏定义和数据库中，安装后立即进入同一业务运行层。玩家 Agent 根据实际启用的交互及授权发现新操作；计算函数的源码不提供给玩家模型。无需为每个新玩法编写 QQ 分发代码或重启平台。

这比修改固定参数更进一步：Agent 能创建新类型、新操作和新函数，组合成新功能。模块不必与任何既定游戏分类对应。

## Agent 操作入口

管理员可直接提出：

> 新建一个协作评估模块。保存每次提交是否有效及它的数值。只把有效提交的数值平方相加作为评估值，玩家可以要求重新计算自己的记录。

后续可以要求：

> 把这个模块改成只统计有效提交的数量，保留原始记录。

Agent 通过 `inspect_runtime` 查询真实函数语法及已创建模块/函数，通过 `inspect_capabilities` 查询命令参数，再提交以下命令：

- `module.put {key, version, manifest}`：创建或整体更新一个模块。`version` 是当前游戏定义版本，模块修订号由服务端递增。
- `module.state {key, version, enabled}`：启停模块。保留原数据；类型、交互、流程、函数随模块停用。
- `module.remove {key, version}`：移除模块定义。有现存数据、引用或依赖时拒绝，须先迁移或退役。

三种命令均走已有身份、版本、事务、幂等和审计服务，并保存变更前安全检查点。旧 Agent 规划和等待事项随定义变化重新校验。不兼容更新使用已有 `definition.migrate`，同时修改模块源定义、展开后的定义及受影响记录；禁止静默删除数据。

模块的成员名称不能覆盖基础定义或其他模块。模块成员通过 `module.put` 更新。已声明依赖不能循环；被启用模块依赖的模块不能直接停用或删除。仍被启用函数、交互或流程引用的计算函数也不能停用。

“游戏控制台 → 运行时模块”可检查实际模块和源码；管理 Agent 是主要创建入口，控制台也提供相同命令的预演及执行。

## 自定义函数与执行

函数定义格式：

```json
{
  "schema": {"type": "object", "properties": {"values": {"type": "array"}}, "required": ["values"]},
  "result": {
    "op": "sum",
    "args": [{
      "op": "map",
      "args": [
        {"path": "input.values"},
        {"op": "multiply", "args": [{"path": "item"}, {"path": "item"}]}
      ]
    }]
  }
}
```

输入 `values: [2, 3]` 返回 `13`。这段逻辑保存在模块中，并非平台内置“平方计分”功能。管理员可换成计数、筛选、条件分段、对象构造或其他组合。

表达式支持 `literal`、`path`、`array`、`object`、函数 `call` 和 `op/args`。当前通用操作包括算术、比较、逻辑、惰性 `if`、字段读取、列表 `map/filter/slice`、汇总、拼接和包含判断。完整真实操作及参数数量由 `inspect_runtime` 返回，不依赖模型猜测。

效果新增：

```json
{
  "type_key": "custom_record",
  "id_from": "target",
  "field": "score",
  "operation": "compute",
  "expression": {
    "call": "custom_score",
    "input": {"object": {"values": {"path": "current.values"}}}
  }
}
```

效果中的 `input` 是此次操作的数据，`current` 是目标记录当前数据，`actor` 是实际身份。流程效果中 `input` 对应已有流程上下文，可进一步访问 `input.input` 和 `input.answers`。函数体只读取显式传入的 `input`；`map/filter` 内增加 `item/index`。不能访问其他记录或绕过玩家归属检查。

函数输入经过 schema 校验，结果经过记录 schema 与引用校验。表达式失败会回滚同一事务里之前的效果、事件与提交。结果记录进实际数据和效果事件；重复合法请求不重新计算或重复修改。

## 扩展边界

当前落地的是**运行时声明式模块和函数**。Agent 可在这些通用操作上创建新功能，平台没有固定玩法模块清单。

当前还不是任意宿主代码插件系统：没有执行 Agent 生成的 Python/JavaScript、自动安装第三方包、接入任意外部 API、自定义前端组件或新增底层计时/随机原语的执行器。遇到超出运行层的底层能力，应明确返回能力缺口。后续可接入隔离代码插件层，但不能把现有表达式配置包装成“什么代码都能写、什么功能都能创建”。

执行器不使用 `eval/exec`，不能读写文件、网络、SQL 或进程。函数禁止递归/循环调用；静态表达式最多1000节点、24层嵌套，执行最多2000次求值、40层深度，列表遍历最多200项，计算结果最多32000字符。这些是平台运行边界，不是特定玩法的规则。

具体玩法的验收应在管理员要求创建相应模块后进行；不存在的玩法无需提前内置。独立扩展层、数据完整性、权限、可执行性、版本和恢复仍需作为平台能力验收。
