# v0.9.1：游戏删除与跨空间管理

## 删除游戏

打开“游戏设置”底部的“删除游戏”，点击后输入完整游戏名称，才能提交永久删除。删除后选择其他游戏；如果没有剩余游戏，则回到创建入口。

`DELETE /api/games/{game_id}` 接收 `{version, confirmation}`，沿用管理登录与请求来源校验。服务器检查名称和版本，并在一个数据库事务中按外键依赖顺序删除：

- 游戏定义、实体、提交、流程、事件与幂等命令记录。
- 参与权限、玩家回合、管理员会话、Agent 任务与工具回执。
- 游戏插件的源码/版本数据库记录、检查点和退役记录。
- QQ 绑定及该游戏的入站、待发和历史消息记录。

其他游戏、模板、平台规则、模型提供者和登录配置保留。全局系统日志保留删除的游戏 ID、名称和各类记录数量，修订号防重用台账不包含原记录正文，继续保留。

这是永久删除，不是归档或回收站；本轮没有增加界面恢复功能。插件安装环境的磁盘缓存，以及插件自行写到宿主机或第三方服务的内容，不在数据库删除事务范围内，不承诺一并擦除。模型/QQ 已经接收的信息也无法由此撤回。

游戏仍有正在运行的管理员/玩家任务、插件安装、入站处理、消息发送或其他会话的跨空间执行时，返回 `GAME_BUSY`。先停止或等待，再重新提交。待审批任务本身尚无副作用，可以随游戏记录删除。删除不通过新建一个空游戏伪装完成，删除后的 ID 返回不存在。

## 同一会话操作其他游戏

当前选中的游戏是会话默认上下文，不再作为管理员 Agent 的操作边界。可以说：

> 找到“匿名博弈”这个游戏，查看它目前的交互，先讨论调整方法。不要改当前这个游戏。

> 按刚才方案修改“匿名博弈”的私聊设置，当前会话继续留在这里。

> 新建一个空白测试游戏，然后在同一会话里配置它。

Agent 先用真实 ID 解析目标，再按需查看配置和工具协议。同名目标不能明确判断时应先澄清。跨空间调用仍在原会话保存回执，不需要用户手工切换空间或复制上下文。

| 工具 | 用途 |
| --- | --- |
| `workspace_list` | 按名称查找或分页列出整个部署的游戏 ID、名称与版本 |
| `workspace_inspect` | 查看目标信息、可用工具及该空间实际插件的输入协议 |
| `workspace_call` | 用明确的目标 `game_id`、`tool`、`arguments` 运行游戏查询、命令、试玩或代码插件 |
| `workspace_create` | 请求创建空白游戏，取得 ID 后可继续配置 |
| `workspace_delete` | 请求永久删除其他游戏，必须提供真实名称及版本 |

查询不需要操作审批。修改和代码执行默认暂停，审批卡明确显示目标游戏名称、ID、操作及完整参数。创建、删除同样需要审批；会话级自动同意也适用。开启自动同意意味着本会话后续的跨空间修改及删除也可能直接执行。

审批绑定原会话空间和目标空间的状态，目标变动后不能复用旧批准。目标空间的工具和插件必须实际存在且输入合法，不能靠套一层跨空间调用绕过校验；不允许递归嵌套或借此修改会话审批设置。玩家 Agent 没有这些管理员跨空间工具，私聊与群聊的授权范围保持原规则。

多个目标分别产生工具步骤和回执，不是一个覆盖整个部署的原子事务：某一步失败不会自动撤销已完成的其他空间操作。不能删除当前正在执行的会话所属游戏；结束任务后可从游戏设置删除，或在其他空间会话中操作。

## 验证范围

隔离测试覆盖关联删除、其他空间与平台配置保留、鉴权、确认名称、过期版本、运行任务阻挡、跨空间查询、审批前无修改、指定目标修改、目标变动使审批过期、未知/嵌套工具拒绝、自动同意，以及同一会话先创建再删除临时空间。

真实 deepseek-flash 已通过 10 项检查：按名称定位其他空间、审批显示目标、批准前无修改、批准后只改目标、原空间保留、回执留在原会话、新建请求审批、新空间落库、删除请求审批、只删除临时空间。验证使用隔离数据库与无 QQ 发送器环境。日常游戏不会被验收脚本修改或删除。界面通过 TypeScript 检查和生产构建，实际浏览器视觉及真实 QQ 投递仍未验收。
