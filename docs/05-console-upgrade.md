# v0.2 控制台升级与验收

日期：2026-10-29。实现范围以本文件及运行说明为准；产品需求中的全部目标尚未完成。

## 参考与取舍

本次研究了 MaiBot 的官方 WebUI 文档与公开截图，主要借鉴其按工作任务组织功能、配置可以直接操作、运行情况可追踪的思路。未复制其源码、品牌、界面素材或默认玩法。MythWeaver 使用自己的灰白/紫色控制台布局，保持管理员从空白定义游戏的定位。

- [WebUI 总览](https://docs.maibot.chat/manual/webui/)
- [配置管理](https://docs.maibot.chat/manual/webui/config-management)：服务商、模型与任务分配。
- [适配器管理](https://docs.maibot.chat/manual/webui/adapter-management)：连接状态与参与策略。
- [命令管理](https://docs.maibot.chat/manual/webui/command-management)：单个交互的参与权限。
- [数据管理](https://docs.maibot.chat/manual/webui/data-management)：数据与运行记录管理。

## 本次实现

| 区域 | 已接入的功能 |
| --- | --- |
| 控制台 | 分组导航、游戏切换、搜索跳转、深浅主题、窄屏布局、真实活动概览 |
| 互动工作台 | 状态筛选、搜索、详情与决定分栏、本机试提交、人工批准数据规则 |
| 游戏数据 | 类型筛选、搜索、动态字段表单、完整记录 ID、导出、原子批量归档 |
| 定义与交互 | 图形字段编辑、定义源文件、启停、每条交互的 QQ 用户权限 |
| 数据规则 | 对自定义记录赋值、增加数值、追加列表；输入或常量取值；最多 10 项；可自动或人工批准执行 |
| 游戏设置 | 暂停接收、自定义命令前缀、自由提交处理方式、白名单、助手工作指示 |
| 参与者 | 自动登记成功参与者、别名、封禁与恢复；不授予平台管理权限 |
| 模型管理 | 多服务商、密钥加密、登记模型、连接测试、计划/讨论任务分别分配、超时与输出参数 |
| 助手工作区 | 计划/讨论历史、耗时、状态、错误代码、预演和原子执行、取消计划、只读讨论 |
| 模板库 | 保存当前定义、导入/导出 JSON、实例化独立游戏；不复制记录和群绑定 |
| 连接与诊断 | NapCat 连接与心跳、绑定群、入站/出站状态、人工重试失败或结果不确定的回复 |
| 历史与检查点 | 追加审计、状态检查点、在线恢复、恢复前自动安全检查点 |

规则通过输入字段提供目标完整 ID，修改仅限同一游戏中的匹配类型。自动执行与人工批准都走相同事务校验；失败不提交部分修改。人工批准依赖目标版本，状态变化后拒绝旧决定。该机制不假设存在角色、属性、战斗、背包或剧情阶段。

模型密钥由 SESSION_SECRET 派生密钥加密，数据库备份必须连同原 `.env` 妥善保存。模型地址可由管理员指定，调用时当前游戏资料将发送到该服务商；不会在未配置服务时代为选择模型。

## 后续缺口

复杂条件/表达式、跨记录查询规则、对象引用选择器、触发器与定时任务、可安装执行模块、完整 Agent 多步工具循环、长任务与长期摘要、多管理员委托、玩家 Web 页面、逐事件撤销与历史分支仍未实现。检查点只恢复游戏业务状态，不撤回已发 QQ 消息，不回退模型/权限/群绑定；详情见运行说明。

当前为单机单工作进程部署，不是公网多人管理服务。没有引入 Docker、NoneBot2 或预设 RPG 系统。
